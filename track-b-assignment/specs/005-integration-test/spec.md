# Spec 005. 통합 테스트

## 배경 / 목적

과제 평가자는 테스트 코드로 설계 의도와 품질을 판단한다. 주요 시나리오가 **HTTP 요청부터 DB까지** 검증되어야 한다.

## 기능 요구사항

- **FR-005-1** 001~004의 모든 AC가 테스트로 검증된다. (테스트 이름에 AC 번호)
- **FR-005-2** 통합 테스트는 서로 독립적이다. 실행 순서에 따라 결과가 바뀌지 않는다.
- **FR-005-3** 동시성 테스트(003)는 결정적으로 통과한다. (10회 반복해도 통과)
- **FR-005-4** `./gradlew :track-b-assignment:test` 한 번으로 모든 테스트가 실행된다. 외부 인프라가 필요하면 테스트가 스스로 띄운다.

## 수용 기준

- **AC-005-1** 모든 AC-00X-Y 가 plan.md의 매핑 표에서 테스트와 연결되어 있다.
- **AC-005-2** 테스트 격리 전략(트랜잭션 롤백 / 테이블 정리 / 컨테이너 재사용)을 plan에 적고 이유를 설명한다.
- **AC-005-3** 운영과 다른 인프라(H2 vs MySQL)로 테스트한다면 그 위험과 대응을 적는다.
