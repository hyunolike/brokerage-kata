# Spec 003. 주문 동시성

## 배경 / 목적

같은 계좌로 여러 기기에서 동시에 주문이 들어오거나, 네트워크 문제로 클라이언트가 같은 요청을 재시도한다.
어떤 경우에도 **주문 가능 금액을 초과해 주문이 접수되면 안 되고**, 같은 요청이 **두 번 처리되면 안 된다.**
서버는 여러 인스턴스로 떠 있다고 가정한다.

## 기능 요구사항

- **FR-003-1** 같은 계좌의 동시 주문/취소/입금에도 잔고 불변식이 지켜진다.
  - `주문 가능 금액 ≥ 0`
  - `예수금 총액 = 입금 합계 − 체결 금액 합계`
  - `묶인 금액 = 접수 상태 주문 금액 합계`
- **FR-003-2** 멱등성: 클라이언트는 주문 생성 요청마다 **멱등 키**를 보낸다. 같은 키의 요청은 한 번만 처리하고, 이후 요청에는 처음과 같은 결과를 돌려준다.
- **FR-003-3** 동시성 제어 방식으로 **Redis 분산락** 또는 **DB 락**(비관적/낙관적/조건부 UPDATE) 중 하나를 선택하고, 선택 근거를 ADR로 남긴다.
- **FR-003-4** 서로 다른 계좌의 요청은 서로를 막지 않는다.

## 수용 기준

- **AC-003-1** Given 주문 가능 500,000원 When 100개 요청이 동시에 10,000원씩 매수 Then 정확히 50건 접수, 주문 가능 0.
- **AC-003-2** Given 같은 멱등 키 When 10개 요청이 동시에 주문 생성 Then 주문은 1건, 모든 응답의 주문 식별자가 같다.
- **AC-003-3** Given 접수 주문 When 같은 주문에 취소 10건 동시 요청 Then 금액 복원은 1번, 불변식 유지.
- **AC-003-4** Given 동시 입금 50건과 동시 주문 50건 When 모두 완료 Then 불변식 유지.
- **AC-003-5** 선택한 방식과 대안 비교가 `docs/adr/`에 있다.
