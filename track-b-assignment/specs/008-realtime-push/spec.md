# Spec 008. 주문 상태 실시간 푸시 (선택)

> 확장 spec. 의존: 007. 권장 시간 60분. 선택 근거는 ADR-0003. 트랙 C spec C006이 이 기능을 사용한다.

## 배경 / 목적

사용자는 주문이 체결되거나 취소되면 **새로고침 없이** 화면에서 바로 알고 싶다.
서버는 여러 인스턴스로 떠 있고, 사용자의 연결은 그중 한 인스턴스에만 붙어 있다.

## 기능 요구사항

- **FR-008-1** 클라이언트는 계좌 단위로 실시간 채널에 연결한다. (WebSocket 또는 SSE — plan에서 선택)
- **FR-008-2** 007의 주문 이벤트가 발생하면 **해당 계좌에 연결된 클라이언트에게만** 상태 변경을 전달한다.
- **FR-008-3** 연결이 끊겼다 다시 붙으면 그 사이의 변경을 놓치지 않는다. (재전송 또는 재조회 — 방식은 plan)
- **FR-008-4** 서버 인스턴스가 여러 대여도 이벤트가 연결된 인스턴스까지 전달된다.
- **FR-008-5** 연결 수, 전송 실패 수를 확인할 수 있다. (009와 연결)

## 수용 기준

- **AC-008-1** Given 계좌 A 채널 연결 When A의 주문 체결 Then 1초 이내에 체결 메시지를 받는다.
- **AC-008-2** Given 계좌 A 채널 연결 When 계좌 B의 주문 체결 Then A는 메시지를 받지 않는다.
- **AC-008-3** Given 연결 끊김 중 주문 취소 When 재연결 Then 취소 상태를 알 수 있다.
- **AC-008-4** 인스턴스 2대 환경에서의 전달 방식을 plan/ADR-0003에 설명한다. (테스트로 증명하면 더 좋다)

## 범위 밖

- 인증 (계좌 식별자를 연결 파라미터로 받는다)
- 실시간 시세
