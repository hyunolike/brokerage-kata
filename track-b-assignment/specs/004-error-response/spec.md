# Spec 004. 예외 처리와 공통 응답 포맷

## 배경 / 목적

클라이언트(트랙 C 프론트엔드 포함)가 모든 API 응답을 **하나의 방식으로** 해석할 수 있어야 한다.

## 기능 요구사항

- **FR-004-1** 모든 성공/실패 응답은 하나의 공통 포맷을 따른다. (포맷은 plan에서 설계)
- **FR-004-2** 실패 응답에는 **기계가 읽는 에러 코드**와 **사람이 읽는 메시지**가 있다.
- **FR-004-3** 요청 검증 실패 시 **어떤 필드가 왜** 틀렸는지 모두 알려준다.
- **FR-004-4** HTTP 상태 코드는 의미에 맞게 쓴다. (검증 400, 없음 404, 상태 충돌 409, 서버 오류 500 등)
- **FR-004-5** 예상하지 못한 예외는 내부 정보(스택 트레이스, SQL)를 노출하지 않고, 서버 로그에는 추적 가능한 정보를 남긴다.
- **FR-004-6** 에러 코드 목록을 README(또는 계약 문서)에 표로 정리한다.

## 수용 기준

- **AC-004-1** Given 수량 0, 가격 누락 주문 When 요청 Then 400, 두 필드의 오류가 모두 응답에 있다.
- **AC-004-2** Given 없는 계좌 When 조회 Then 404, 에러 코드로 "계좌 없음"을 구분할 수 있다.
- **AC-004-3** Given 잔고 부족 When 주문 Then 도메인 에러 코드로 구분할 수 있다. (상태 코드 선택은 ADR 또는 plan에 근거)
- **AC-004-4** Given 서버 내부 예외 When 요청 Then 500, 응답 본문에 스택 트레이스가 없다.
- **AC-004-5** Given 잘못된 JSON 본문 When 요청 Then 400 공통 포맷.
