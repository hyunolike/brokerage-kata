# 단계적 힌트

## 준비
1. `./kata status`로 현재 문제와 단계를 확인한다. 현재 단계 문서와 사용자의 현재 코드(`src/main`, `src/test` 또는 `src/`, `tests/`)를 읽는다.
2. `.kata/hints.log`에서 **이 문제·이 단계**에 이미 준 힌트 레벨을 확인한다. 이번 힌트는 그다음 레벨이다. (최대 3)

## 레벨
| 레벨 | 형태 | 예 |
|---|---|---|
| 1. 방향 | 질문으로 되묻기. 어디를 봐야 하는지만 | "매수와 매도에서 '더 좋은 가격'의 정의가 같나요?" |
| 2. 개념 | 필요한 개념/패턴/자료구조의 **이름**과 왜 필요한지 | "정렬된 키로 최소/최대를 꺼내면서 같은 키끼리 묶어야 하면 어떤 Map이 있을까요?" 다음 레벨에서만 이름을 말한다 |
| 3. 구조 | 클래스/메서드 **책임 목록**이나 **의사코드 3~6줄** (컴파일되는 코드 금지) | "1) 반대편 최우선 레벨 조회 2) 교차 여부 확인 …" |

- `$ARGUMENTS`에 막힌 지점이 있으면 그 지점에 대해서만 준다.
- 사용자의 코드에 버그가 있어도 위치를 직접 짚지 않는다. 레벨 1은 "어떤 입력으로 테스트해 보면 좋을까요?", 레벨 3에서야 "○○ 메서드의 경계 조건"처럼 범위를 좁힌다.
- 레벨 3 이후에도 막혀 있다면 `/review` 또는 `/solution`을 선택지로 알려준다.

## 기록
힌트를 준 뒤 `.kata/hints.log`에 한 줄 추가한다 (Bash `echo ... >>`):
```
<YYYY-MM-DD>	<문제 폴더명>	stage <N>	L<레벨>	<한 줄 요약>
```
