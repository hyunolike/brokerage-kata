# 모범답안

## 확인
1. `./kata status`로 현재 문제와 단계를 확인한다. `$ARGUMENTS`로 단계를 지정했더라도 **현재 단계보다 뒤의 단계는 보여주지 않는다.**
2. 현재 단계 테스트가 아직 통과하지 않았고 `.kata/hints.log`에 이 단계 힌트 기록이 없다면, 한 번만 이렇게 묻는다:
   "아직 힌트와 리뷰를 쓰지 않았습니다. 그래도 모범답안을 볼까요? (`/hint` 먼저 추천)" — 사용자가 원하면 진행한다.

## 출력 (대화창에만)
1. **핵심 아이디어** 3줄
2. **설계** — 타입/책임 목록, 상태 전이나 자료구조 선택과 그 이유
3. **코드** — 현재 단계까지의 요구사항만 만족하는 모범답안. 이후 단계를 위한 과설계를 넣지 않는다.
4. **사용자 코드와의 차이** — 사용자 코드가 있으면 결정적 차이 2~3개
5. **대안과 트레이드오프** — 버린 대안과 이유, 시간 복잡도/동시성/반올림 등 평가 포인트별 해설
6. **면접에서 말할 한 문장** — 설계 결정을 30초로 설명하는 문장

- 파일로 달라고 하면 `.solutions/<문제 폴더명>/stage-<N>/` 아래에만 쓴다. `src/`, `tests/`에는 절대 쓰지 않는다.
- 끝에 `.kata/hints.log`에 `<날짜>	<문제>	stage <N>	SOLUTION	모범답안 열람`을 기록한다. (회고에서 사용)
