# p2. 호가창 체결 엔진 (Order Book)

> 자료구조 선택 + 매칭 알고리즘 · 제한 시간 **50분** (3단계)

## 배경

한 종목의 **호가창(order book)** 을 메모리에서 관리하고, 새 주문이 들어오면
반대편 호가와 **가격 우선 → 시간 우선** 원칙으로 체결시키는 엔진을 만든다.

## 단계 구성

| 단계 | 파일 | 권장 시간 |
|---|---|---|
| 1 | `stages/stage-1.md` | 15분 |
| 2 | `stages/stage-2.md` | 15분 |
| 3 | `stages/stage-3.md` | 20분 |

> ⚠️ 현재 단계를 끝내기 전에는 다음 단계 파일과 다음 단계 테스트 파일을 열지 않는다.

## 평가 포인트

- **자료구조 선택 근거** — `PriorityQueue` vs `TreeMap<Long, Deque<...>>` vs 정렬 리스트. 왜 그것인가?
- **시간 복잡도** — 주문 등록 / 최우선 호가 조회 / 호가창 N단계 조회 / 체결 / (보너스) 취소 각각을 말로 설명할 수 있는가
- 매수는 높은 가격, 매도는 낮은 가격이 우선이라는 **비대칭을 중복 없이** 표현했는가
- 부분 체결 후 **잔량 처리**와 빈 가격 레벨 정리가 정확한가
- 시간 우선을 "시각"이 아니라 **도착 순서**로 보장하는가
