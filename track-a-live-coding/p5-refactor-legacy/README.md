# p5. 레거시 리팩터링 (Refactor Legacy)

> 안전망 먼저, 그다음 리팩터링 · 제한 시간 **60분** (3단계)

## 배경

5년 동안 여러 사람이 덧대 온 **수수료 계산 서비스**가 있다. 동작은 한다.
하지만 긴 조건문, 복사·붙여넣기, 매직 넘버, `double` 금액, 숨은 시간 의존성, 전역 가변 상태가 가득하다.
이번 분기에 새 수수료 정책을 넣어야 하는데, 지금 구조로는 어디를 고쳐야 할지 아무도 확신하지 못한다.

> 이 문제의 `src/main` 코드는 **의도적으로 나쁘게** 작성되어 있다. 이 레포에서 유일하게 "완성된" 프로덕션 코드다.

## 단계 구성

| 단계 | 파일 | 권장 시간 |
|---|---|---|
| 1 | `stages/stage-1.md` | 20분 |
| 2 | `stages/stage-2.md` | 25분 |
| 3 | `stages/stage-3.md` | 15분 |

> ⚠️ 현재 단계를 끝내기 전에는 다음 단계 파일과 다음 단계 테스트 파일을 열지 않는다.

## 평가 포인트

- **테스트 먼저** — 코드를 고치기 전에 현재 동작을 고정하는 특성 테스트(characterization test)를 깔았는가
- **작은 걸음** — 한 번에 하나씩 바꾸고 매번 테스트를 돌렸는가 (커밋 단위로 보이게)
- **버그처럼 보이는 동작의 처리** — 몰래 고치지 않고, 기록하고, 결정을 질문했는가
- **시간 의존성 분리** — `new Date()` 같은 숨은 입력을 테스트 가능한 형태로 바꿨는가
- **확장 구조** — 새 정책을 넣을 때 기존 분기를 건드리지 않는가

## 시작 방법

```bash
./kata start p5
```

1. 타이머 시작 → 2. `NOTES.md`에 질문 목록 + **이상 동작 목록** → 3. `Stage{N}Test.java` 잠금 해제 후 진행 → 4. `./kata next p5` → 5. `/retro p5`
