# Stage 1. 현재 동작을 고정하는 테스트

## 요구사항

`FeeService.calc(...)`의 **현재 동작을 그대로 고정**하는 특성 테스트를 작성한다.

- 이 단계에서는 **프로덕션 코드를 수정하지 않는다.**
  (테스트를 위해 꼭 필요한 최소한의 변경이 있다면 무엇을 왜 바꿨는지 `NOTES.md`에 기록)
- "올바른 값"이 아니라 **"지금 나오는 값"** 을 기대값으로 쓴다.
- 버그처럼 보이는 동작도 일단 그대로 고정하고, `NOTES.md`의 이상 동작 목록에 적는다.

## 파라미터

| 파라미터 | 값 |
|---|---|
| `mkt` | `KR`, `US` |
| `grd` | `NORMAL`, `VIP`, `EMP`, `null` |
| `ch` | `MTS`, `HTS`, `API`, `BRANCH` |
| `sd` | `B`(매수), `S`(매도) |
| `prc`, `qty` | 가격, 수량 |
| `joinDt` | 가입일 `yyyyMMdd` |
| `evt` | 신규가입 이벤트 대상 여부 |

## 커버해야 할 것 (최소)

- 시장 × 등급 × 채널의 주요 조합
- 국내 매도 시 거래세
- 지점(BRANCH) 최소 수수료
- 반올림/버림 방식이 다른 분기
- 신규가입 이벤트 (가입 후 90일 경계 — 오늘 날짜에 의존한다는 점에 주의)
- 잘못된 입력 (`qty <= 0`, 알 수 없는 시장/등급, `null`)
- `FeeService.lastFee` 전역 상태

## 팁

- 조합이 많으면 `@ParameterizedTest` + `@CsvSource`로 표처럼 만든다.
- 커버리지 도구(IntelliJ Run with Coverage)로 **빠진 분기**를 찾는다.
- 일부러 프로덕션 코드의 숫자 하나를 바꿔 보고 테스트가 깨지는지 확인한다. (mutation 감각)
