# Stage 2. 동작을 유지하며 리팩터링

## 요구사항

Stage 1의 테스트가 **계속 통과하는 상태를 유지하면서** `FeeService` 내부를 리팩터링한다.

### 제약
- `FeeService.calc(...)`의 **시그니처는 바꾸지 않는다.** (`OrderSettlement` 등 다른 팀 호출부가 있음)
- `OrderSettlement`는 수정하지 않는다.
- Stage 1에서 고정한 동작은 **버그처럼 보여도 그대로 유지**한다. 고치고 싶다면 `NOTES.md`에 제안만 적는다.

### 목표 (우선순위 순)
1. 오늘 날짜 의존성 제거 — 시간(가입일 경과 일수)을 **주입**할 수 있게 한다.
2. 시장/등급/채널별 규칙을 **한눈에 보이는 구조**로 옮긴다. (표, 전략, enum 등 방식은 자유)
3. 복사·붙여넣기된 이벤트 로직, 매직 넘버를 정리한다.
4. (선택) 금액 계산을 `BigDecimal`로 바꾸는 것을 검토한다. 단, 결과가 **한 푼이라도 달라지면** Stage 1 테스트가 알려줄 것이다. 달라진다면 왜 그런지 설명할 수 있어야 한다.

### 진행 방식
- 한 번에 한 가지 리팩터링 → 테스트 실행 → (가능하면) 커밋. 이 리듬을 지킨다.
- 새로 만든 구조(예: 정책 객체)에는 단위 테스트를 추가해도 좋다.
