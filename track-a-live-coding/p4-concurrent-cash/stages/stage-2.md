# Stage 2. 동시 주문

## 요구사항

같은 계좌로 **여러 스레드에서 동시에** 주문이 들어온다.

1. 어떤 경우에도 **예수금이 음수가 되면 안 된다.** (초과 주문 금지)
2. 성공한 주문 금액의 합 + 남은 예수금 = 입금 총액 이어야 한다.
3. **같은 주문ID**로 요청이 여러 번(동시에) 들어와도 **한 번만** 차감한다. (클라이언트 재시도 대비)
   - 두 번째 이후 요청은 첫 요청과 같은 결과를 돌려준다.
4. **서로 다른 계좌**의 주문은 서로를 기다리지 않아야 한다.
5. 동시에 입금과 주문이 섞여 들어와도 금액이 맞아야 한다.

## 검증 시나리오 (멀티스레드 테스트로 작성)

| # | 상황 | 기대 결과 |
|---|---|---|
| 1 | 예수금 500,000, 스레드 100개가 동시에 서로 다른 주문ID로 10,000씩 주문 | 정확히 50건 성공, 예수금 0 |
| 2 | 예수금 100,000, 스레드 10개가 **같은 주문ID**로 동시에 30,000 주문 | 1번만 차감, 예수금 70,000 |
| 3 | 계좌 A에 오래 걸리는 작업이 진행 중일 때 계좌 B 주문 | B 주문은 A를 기다리지 않고 완료 |

## 테스트 작성 팁

- 모든 스레드를 `CountDownLatch`로 **동시에 출발**시킨다.
- 테스트가 운 좋게 통과하지 않도록 반복 실행(`@RepeatedTest`)도 고려한다.
- 동기화를 일부러 빼고 테스트가 **실패하는 것을 먼저 확인**하라.
