# Stage 3. 체결과 취소, 금액 복원

## 요구사항

주문 금액은 주문 시점에 바로 사라지는 것이 아니라 **주문 묶음(hold)** 상태로 잡혀 있다가,
체결되면 확정 차감되고, 취소되면 **미체결분만큼 예수금으로 복원**된다.

1. **체결**: `체결(주문ID, 체결 금액)` — 해당 주문의 묶인 금액에서 체결 금액만큼 확정 차감한다.
   - 누적 체결 금액은 주문 금액을 넘을 수 없다.
2. **취소**: `취소(주문ID)` — 아직 체결되지 않은 묶인 금액 전부를 예수금으로 되돌린다.
   - 이미 취소된 주문을 다시 취소하면 **아무 일도 일어나지 않는다.** (동시에 여러 번 들어와도 한 번만 복원)
   - 전량 체결된 주문은 취소할 수 없다.
   - 취소된 주문에는 체결을 반영할 수 없다.
3. 조회: 계좌의 `예수금(주문 가능)`, `묶인 금액 합계`를 알 수 있다.
4. **같은 주문에 체결과 취소가 동시에** 들어와도 금액이 맞아야 한다.
   (체결이 먼저 반영되면 나머지만 복원, 취소가 먼저면 체결은 거부)

## 입출력 예시

예수금 100,000

| # | 요청 | 예수금 | 묶인 금액 |
|---|---|---|---|
| 1 | 주문 O1 60,000 | 40,000 | 60,000 |
| 2 | O1 체결 20,000 | 40,000 | 40,000 |
| 3 | O1 취소 | 80,000 | 0 |
| 4 | O1 취소 (다시) | 80,000 | 0 (변화 없음) |
| 5 | O1 체결 10,000 | **거부** (취소된 주문) | 0 |

## 검증 시나리오 (멀티스레드)

| # | 상황 | 기대 결과 |
|---|---|---|
| 1 | 같은 주문에 취소 요청 10개 동시 | 복원은 정확히 1번 |
| 2 | 60,000 주문에 `체결 20,000`과 `취소`를 동시에 | 결과는 두 가지 중 하나: (체결 후 40,000 복원) 또는 (60,000 복원 + 체결 거부). 금액 합계는 항상 입금액과 같다 |
