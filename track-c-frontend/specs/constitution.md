# Constitution — 트랙 C 불변 원칙

1. **계약이 먼저다.** 화면은 `contracts/brokerage-api.yaml`을 기준으로 만든다. 계약에 없는 필드를 가정하지 않는다.
2. **돈 계산의 진실은 서버다.** 화면의 금액 계산(예상 주문 금액 등)은 안내용이고, 최종 판단은 서버 응답을 따른다.
3. **수용 기준 = 테스트.** 모든 `AC-C*`는 테스트와 연결되고 테스트 이름에 AC 번호를 적는다.
4. **사용자 관점으로 테스트한다.** 구현 세부(state, 클래스명)가 아니라 역할(role)·텍스트로 요소를 찾는다.
5. **모든 비동기 화면은 세 가지 상태를 가진다.** 로딩 / 성공 / 실패.
6. **돈이 걸린 버튼은 두 번 눌리지 않는다.** 제출 중 비활성화, 서버 멱등 키와 함께 설계한다.
7. **의존성 추가는 plan에 근거를 남긴다.** (예: 상태 관리, 서버 상태 캐시, 폼 라이브러리, MSW)
